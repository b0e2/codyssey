# 트러블슈팅

## 1. 볼륨 삭제 시 "volume is in use" 에러

**문제**: 실습 후 정리 과정에서 볼륨 삭제 시도 시 에러 발생

```
$ docker volume rm mydata
Error response from daemon: remove mydata: volume is in use - [4cf2acb7c24f11bb33d7745d41342008d9545deb1a063bce51f6b8230cb0deb8]
```

**원인 가설**: `vol-test2` 컨테이너가 아직 `mydata` 볼륨을 사용 중인 상태(실행 중)라서 삭제가 거부됨

**확인**: `docker ps`로 `vol-test2`가 여전히 실행 중인지 확인

**해결**: 볼륨을 사용 중인 컨테이너를 먼저 삭제한 후 볼륨 삭제

```
$ docker rm -f vol-test2
$ docker volume rm mydata
```

## 2. 터미널 테마 사용 시 로그 녹화(`script`)가 이스케이프 코드로 깨짐

**문제**: 터미널 조작 로그를 `script` 명령으로 녹화했는데, 결과 파일을 열어보니 명령어와 출력이 ANSI 이스케이프 코드(색상/커서 이동 제어 문자)와 뒤섞여 사람이 읽을 수 없는 상태로 저장됨. 예를 들어 `mkdir box`가 `mkdirbox`처럼 붙어서 기록되거나, 자동완성으로 제안된 텍스트까지 함께 녹화됨.

**원인 가설**: `script` 명령은 터미널 화면에 그려지는 모든 원시 바이트를 그대로 저장하는 도구다. 당시 사용 중이던 **zsh 테마(powerlevel10k)**가 현재 브랜치, 실행 시간, 성공/실패 아이콘 등을 매 프롬프트마다 표시하기 위해 색상 코드와 커서 이동 제어 문자를 지속적으로 출력하고 있었는데, `script`가 이 장식 요소까지 원본 그대로 저장하면서 실제 입력한 명령어와 뒤섞인 것으로 확인됨. 추가로 zsh의 자동완성 제안(autosuggestions) 기능이 화면에 표시하는 회색 텍스트도 함께 캡처되어 문제를 키움.

**확인**:
- 기존 맥에서 프롬프트만 임시로 단순화(`PROMPT='$ '`)하거나 `bash --norc`로 셸 설정 파일 로드를 배제해 재시도했으나, VSCode 통합 터미널의 Shell Integration 기능이 별도로 브랜치 정보 등을 주입하고 있어 완전히 해결되지 않음을 확인
- 이후 서울캠퍼스 아이맥(powerlevel10k가 설정되어 있지 않은 환경)으로 작업 환경을 옮겨 동일한 `script` 녹화 절차를 재실행한 결과, 이스케이프 코드나 자동완성 텍스트 없이 명령/출력이 그대로 기록되는 것을 확인 → 원인이 zsh 테마(powerlevel10k)임을 최종 확인

**해결**: 원인이 특정 환경(기존 맥의 zsh + powerlevel10k 설정)에 있음을 확인한 뒤, 이후 로그 녹화는 해당 테마가 설정되지 않은 환경에서 진행하는 방식으로 정리했다. 문제를 도구(`script`) 탓으로 단정하기 전에, 환경을 교체해 재현 여부를 비교함으로써 원인을 특정할 수 있었다.
