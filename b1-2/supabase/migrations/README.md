# 마이그레이션 실행 순서

Supabase 대시보드 > SQL Editor 에서 순서대로 실행한다.

| 파일 | 하는 일 | 되돌리기 |
|---|---|---|
| `20260910_add_tags.sql` | 과목을 태그 배열로 옮긴다 | `20260910_rollback_tags.sql` |
| `20260911_user_scoped_rls.sql` | 기록에 주인을 지정하고 접근을 사용자 기준으로 바꾼다 | `20260911_rollback_to_anon.sql` |
| `20260911_drop_subject.sql` | 쓰지 않는 과목 컬럼을 지운다 | 불가 |

## 원칙

되돌릴 수 없는 변경은 되돌리는 SQL을 먼저 만든 뒤에 실행한다.
접근 정책과 컬럼 제약은 코드를 되돌려도 복구되지 않는다.

과목 컬럼을 지우는 것은 마지막에 한다. 태그로 옮긴 직후에 지웠다면
문제가 생겼을 때 돌아갈 곳이 없다.

## 접근 정책을 바꿀 때

순서를 지킨다. 예전 정책을 먼저 지우면 그 사이 화면의 모든 요청이 실패한다.

1. 기존 기록에 주인을 지정한다
2. 주인 없는 기록이 없는지 확인한다
3. 컬럼을 필수로 바꾼다
4. 예전 정책을 지운다
5. 새 정책을 만든다
